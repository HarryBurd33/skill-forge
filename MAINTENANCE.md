# Project maintenance and usage policy

Preserve the existing public repository, Git history, user changes and draft pull-request workflow. Use one canonical skill source; generated portable prompts and managed installations must match the approved source. Never force-push, publish private sessions or replace a working version with a failed candidate.

Use suitable models and ordinary effort for bounded routine work. Escalate reasoning only for consequential uncertainty, repeated failure or important independent review, and record the reason. Consider an already available reliable local/free model only after its task checks establish suitability. Do not install a model, spend credits or replace frozen evaluation arms merely to save usage. No qualified local/free evaluation runtime has been established for this release.

Frozen behavioral evaluations retain their recorded model/settings, inputs, criteria and independent-review boundaries. Exact serving model/build and per-task token consumption are unknown when the host does not expose them. Do not label an inferred model ID as measured. Higher reasoning or multiple workers must earn their cost through a useful bounded result, not a larger number of questions.

At meaningful checkpoints record completed deliverables, retries, elapsed active work, observed account usage and unavailable measurements. Exclude actual inactive/quota waits only through a prospective carry-forward record; never reset the authorized candidate or effort allowance. Keep private controls and raw transcripts outside the publication allowlist. Stop at failed required checks, preserve the candidate and prior active source, and retain rollback.

Commit reviewable milestones to the existing draft branch. Inspect the exact publication selection, push through the available authorized connection, and verify the remote commit and files. A local commit is not a successful push. Update HANDOFF.md with known remote state and any local-only or blocked work.
