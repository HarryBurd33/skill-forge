| [Matt Pocock: grill-me / grilling](https://github.com/mattpocock/skills/tree/49dd158d1076134a641b33efb035946536778336/skills/productivity) | `grill-me` is a manual-only wrapper invoking `grilling`. The implementation organizes dependent decisions into rounds and delegates discoverable facts. It asks the entire available decision frontier, phrases recommendations so “yes” accepts them, visits every branch, then requires confirmation. | Adapt dependency order and factual research. Ask only questions whose answers matter to the deliverable. Allow smaller rounds, disagreement, explicit defaults, and early drafting; omit exhaustive exploration and mandatory confirmation. |
| [Anthropic: skill-creator](https://github.com/anthropics/skills/tree/dbd4588f9e1033efb41dad4bef2f7947c8993d44/skills/skill-creator) | Already creates and improves skills; runs no-skill or previous-version baselines; records assertions, timing, tokens, and benchmark variation; offers a review viewer and blind comparison. Description optimization tests positive/negative activation prompts, separates training and held-out cases, and applies the selected description. Its scripts invoke Claude. | Reuse the comparison approach conceptually. Do not claim evaluation or iteration as new inventions. Add a portable interview and durable records, separate personal and shared lessons, freeze acceptance checks before candidates, and adopt successful updates with rollback. Avoid requiring a specific CLI, browser reviewer, or human approval after every passing update. |
| [OpenAI: skill-creator](https://github.com/openai/skills/tree/49f948faa9258a0c61caceaf225e179651397431/skills/.system/skill-creator) | Gives concrete-example discovery, concise authoring, progressive disclosure, reusable resources, initialization, metadata validation, and iteration from use. | Use those authoring principles. Keep setup/history docs outside the installed skill's workflow references. Implement small original helpers rather than copying the initializer or validator. Treat optional host UI metadata separately from common instructions. |
| [Agent Skills specification](https://agentskills.io/specification) | Defines a skill directory and `SKILL.md` metadata, optional resources, and relative references. Tool declarations have host-dependent support. | Use `name` and `description` as the common foundation. Keep generated skills self-contained. Validate the supported metadata subset and packaged references; a structural pass does not establish behavioral quality. |
| [OpenAI Astra guidance](https://developers.openai.com/blog/rethinking-skills-and-prompts-for-gpt-6-astra) | Recommends focused discovery descriptions, conditional detail, fewer unnecessary procedural constraints, and clear completion boundaries. | Keep the root skill a concise router. Define what “done” means, make deeper references conditional, and continue already-authorized work without ritual approvals. |
| [Agent Skills evaluation guide](https://agentskills.io/skill-creation/evaluating-skills) | Describes realistic cases, separate contexts, paired baselines, evidence-based grading, and qualitative comparison. | Use this modest case-and-output approach instead of inventing an evaluation service. Unlike its exploratory suggestion to add assertions after an initial run, lock criteria before evaluating an adoption candidate. Label simulations, real executions, and unavailable checks distinctly. |

## What Skill Forge adds

The intended contribution is the combination: interviewing scaled to unresolved decisions; three routes (create, improve a target, improve the builder); reusable questions with dependencies and lifecycle; portable resumable briefs; and evidence-gated local adoption with version history. A personal preference is not a shared improvement. Passing formatting checks cannot authorize a behavioral change. An inconclusive or unavailable behavioral check leaves the prior version active.

The first release deliberately avoids a hosted service, paid evaluator requirement, marketplace dependency, autonomous background learning, and claims of universal model compatibility. It does not train a model or create automatic memory between unrelated chats. “Learning” means changes to files, backed by recorded examples and checks.

## Source and license review

Pinned source files and skill-local licenses were fetched, not inferred from GitHub visibility. Matt Pocock's repository has MIT terms. Anthropic's and OpenAI's inspected skill-creator directories each contain Apache-2.0 terms; neither was assumed MIT because other files might use different terms. Recursive repository inventories showed no additional `NOTICE` file in either inspected creator directory. The records cover only the listed material, not every file in those repositories.

No third-party prose, code, templates, or assets are incorporated into this release. The original Skill Forge material is MIT. Future copying must preserve the relevant license, copyright, modification, and notice requirements; a source link alone is not a substitute.
