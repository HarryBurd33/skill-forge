# Execution protocol

1. Freeze and hash this design, existing v0.2.0 source and candidate source before either arm. The author may read development-cases.json, frozen-criteria.json, evaluator.md and this protocol; do not open heldout-cases.HIDDEN.json until candidate source is frozen. No model execution is part of this design deliverable.
2. Use fresh fork_turns=none contexts per case AND arm. Supply only that arm's canonical skill and referenced resources (or frozen self-contained export), the neutral harness below, current initial user turn, supplied context, allowed capabilities and an output path. Do not supply future followups, criteria answers, other case prompts, arm comparison outputs or private original conversation.
3. Multi-turn cases: record/end each response, then deliver exactly the next scripted user followup. Never expose future corrections initially. Separate neutral runner from judge. If concurrency slots are needed for D05, run other cases serially or finish them first; do not fake unavailable agents. Tool permissions in scenario override actual host capabilities.
4. Neutral harness: "Follow the supplied Skill Forge source for this case. Respond to the user task under the stated capabilities. Do not read other versions, evaluation answers or other cases. Use only the given output/workspace paths. Save the exact assistant response and actual action records; do not write a self-grade. If a capability is absent, be honest. End after responding to the current user turn; a later turn will arrive separately."
5. Save raw per-turn responses, child task/returns and action records. Record UTC timestamp, exposed model/host metadata, source tree digest, user input digest, token/runtime errors and evaluator digest. Use identical tool envelopes and turn order for both arms.
6. One eligible execution per arm/case. If wrong source, leaked followup, context contamination, retrieval/launch timeout or interrupted protocol occurs, mark invalid/inconclusive, retain it, preregister any paired retry before seeing new output and use no favorable selection. Do not retry ordinary behavior failures to hunt a pass.
7. Grade outputs in a fresh independent context against frozen specific conditions. Reveal heldout cases to executor/judge only after source freeze. After that point they are consumed; any implementation patch requires fresh independently authored holdouts or transparently treating them as diagnostics. Keep total candidate patches <= 3 and 90-minute research/build/evaluation effort limit.
8. Gate automatic adoption only on observed passing required checks and narrow measured benefit. Keep active baseline on failure/unavailable/inconclusive, preserve candidate/evidence, do not relax criteria. Publish only sanitized intentionally public records, never private machine/user context.
