# Frozen evaluator

Freeze: before candidate implementation; baseline Skill Forge 0.3.1 versus candidate 0.4.0. These controls are outside candidate files.

Use identical case requests, fixture bytes, tool availability and effort bounds for baseline and candidate. Run each in a fresh model context with the corresponding actual skill installed/read. A prompt saying a tool exists does not prove a tool call. Retain complete model output and real tool-call/output transcripts. Report actual serving configuration when available; do not infer it from requested model labels.

Evaluate each case independently using its listed critical conditions and exact expected conditions. Mark each condition PASS/FAIL/UNEXECUTED, linking output excerpts or real tool evidence. A critical omission/fabricated execution is FAIL. If needed execution cannot run, mark UNEXECUTED; neither a static review nor a narrated hypothetical run becomes PASS. Case pass is binary and requires every applicable condition PASS. No partial-credit average can mask a critical failure.

Adoption requires every candidate development and held-out case to pass, all relevant existing regressions to pass, and the specified N1 self-contained Anatomy outcome to improve by at least one satisfied condition relative to comparable baseline behavior. Record baseline and candidate result per condition. Do not award improvement merely for adding files or repeating a tool name. N2 truthful missing-tool/provider fallback is a mandatory preservation regression already required by baseline, and baseline success on N2 is expected. N2 never contributes to benefit scoring. If baseline already satisfies N1, leave this improvement gate unmet; do not change it after results. A compatible available optional REA runtime/provider must additionally perform an actual static analysis on an original supplied JavaScript fixture, retaining real result and limitations; when genuinely unavailable, document that condition and preserve N2 without pretending execution.

The constructor may inspect development cases only until the candidate is frozen by a complete package hash. Held-out cases are revealed only to independent runners/grader after that freeze. Any post-heldout fix is a new candidate and requires fresh held-out evidence, rather than treating the exposed cases as still unseen.

Deterministic source/package checks supplement model cases: validate metadata/links, all copied helper import closures, real renderer/CSS hashes against pinned upstream files, complete notices, source revision provenance, compile/check relevant original helper code, and relocate a generated target with Forge path hidden. Build an original mechanism using the actual bundled renderer; parse resulting SVG, inspect actual light/dark desktop/mobile images and verify model-derived readout, keyboard/reduced-motion behavior if claimed. Atomic add-anatomy must leave an existing customized target unchanged on conflicts/failure, copy a complete dependency slice on success, and be idempotent on an identical repeat. Do not execute unreviewed upstream installers. REA/provider tests require real observed tool evidence; unavailable optional engines do not justify universal capability claims.

Review-first case pass requires observing no target write or full artifact in its transcript. Draft-now/file-text case pass requires pre-build current contract/ordered steps/check ledger and correct artifact plus compact external resume handoff. Existing regression evidence is reusable only with the same relevant unchanged artifact/contract and a stated justification.

Prospective design amendment v2 (before source edits or any baseline/candidate runs): N2 reclassified as established preservation and min_delta reduced to 1 on N1 only. All six cases and all applicable critical conditions remain mandatory. No observed failures were rescored; all earlier control documents are preserved with -pre-benefit-amendment names.
